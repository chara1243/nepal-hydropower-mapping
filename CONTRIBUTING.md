# Contributing

1. Open an issue describing the problem or proposed improvement.
2. Keep changes focused and explain any methodological changes.
3. Test the notebook from a fresh runtime using documented sample data or clearly describe any untested parts.
4. Update the README when input requirements, outputs, dependencies, or classification rules change.
5. Do not commit raw datasets, credentials, private information, or generated outputs unless redistribution is explicitly permitted and the files are necessary.

For methodological changes, document the rationale and any effect on comparability with earlier outputs.
